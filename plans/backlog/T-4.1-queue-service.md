# T-4.1 — Queue Service

**Phase:** Async Processing
**Layer:** Backend
**Status:** Backlog
**Estimated Effort:** 1–2 hours
**Dependencies:** T-1.2

---

## Objective

Implement the `QueueService` adapter using BullMQ for development. Abstract queue behind domain interface for future SQS swap.

---

## Acceptance Criteria

- [ ] `BullMQQueueService` implementing `QueueService` interface
- [ ] `push()` method adds job to `message-processing` queue
- [ ] Job payload includes `conversationId`, `messageId`, `from`, `text`, `clinicId`
- [ ] Queue configured with retry logic (3 attempts, exponential backoff)
- [ ] Dead Letter Queue for permanently failed jobs
- [ ] `QueueModule` providing `QueueService` via DI

---

## Implementation Steps

### 1. BullMQ Queue Service

Create `src/infrastructure/queue/bullmq-queue.service.ts`:
```typescript
@Injectable()
export class BullMQQueueService implements QueueService {
  private queue: Queue;

  constructor(private configService: ConfigService) {
    this.queue = new Queue('message-processing', {
      connection: { host: configService.get('REDIS_HOST', 'localhost'), port: 6379 },
      defaultJobOptions: {
        attempts: 3,
        backoff: { type: 'exponential', delay: 1000 },
        removeOnComplete: 100,
        removeOnFail: 500,
      },
    });
  }

  async push(job: QueueJob): Promise<void> {
    await this.queue.add('process-message', job);
  }
}
```

### 2. Queue Module

Create `src/infrastructure/queue/queue.module.ts`:
```typescript
@Module({
  providers: [
    { provide: QUEUE_SERVICE, useClass: BullMQQueueService },
  ],
  exports: [QUEUE_SERVICE],
})
export class QueueModule {}
```
