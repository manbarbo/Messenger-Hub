# T-5.2 — Error Handling & Validation

**Phase:** API Layer
**Layer:** Backend
**Status:** Backlog
**Estimated Effort:** 1–2 hours
**Dependencies:** T-5.1

---

## Objective

Implement global error handling, request validation pipes, and proper HTTP error mapping.

---

## Acceptance Criteria

- [ ] Global exception filter catches domain errors and maps to HTTP status codes
- [ ] `SlotAlreadyBookedError` → 409
- [ ] `SlotNotFoundError` → 404
- [ ] `ClinicNotFoundError` → 404
- [ ] `PastDateError` → 400
- [ ] `LLMProviderError` → 502
- [ ] `ValidationError` → 400
- [ ] Infrastructure errors (DB, queue) → 500 (never expose raw errors)
- [ ] Validation pipe using class-validator for all DTOs
- [ ] Error responses follow consistent format: `{ error: string, message: string }`

---

## Implementation Steps

### 1. Domain Exception Filter

Create `src/presentation/filters/domain-exception.filter.ts`:
```typescript
@Catch()
export class DomainExceptionFilter implements ExceptionFilter {
  catch(exception: Error, host: ArgumentsHost) {
    const response = host.switchToHttp().getResponse();
    
    const statusMap = new Map([
      [SlotAlreadyBookedError.name, 409],
      [SlotNotFoundError.name, 404],
      [ClinicNotFoundError.name, 404],
      [PastDateError.name, 400],
      [LLMProviderError.name, 502],
      [ValidationError.name, 400],
    ]);

    const status = statusMap.get(exception.constructor.name) || 500;
    const message = status === 500 ? 'Internal server error' : exception.message;

    response.status(status).json({ error: exception.constructor.name, message });
  }
}
```

### 2. Validation Pipe

Configure global validation pipe in `main.ts`:
```typescript
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,
  forbidNonWhitelisted: true,
  transform: true,
}));
```

### 3. Apply Filters

Register global filter in `main.ts`:
```typescript
app.useGlobalFilters(new DomainExceptionFilter());
```
