# T-2.4 — CQRS Queries

**Phase:** Backend Core
**Layer:** Backend
**Status:** Backlog
**Estimated Effort:** 1–2 hours
**Dependencies:** T-2.1, T-2.2

---

## Objective

Implement CQRS query handlers for data retrieval: `ListConversationsQuery`, `GetConversationDetailQuery`.

---

## Acceptance Criteria

- [ ] `ListConversationsQuery` + handler: returns paginated conversations with optional status filter
- [ ] `GetConversationDetailQuery` + handler: returns conversation with messages and AI traces
- [ ] Queries combine data from both PostgreSQL (clinic name) and MongoDB (conversations, messages, traces)
- [ ] Pagination works correctly with total count
- [ ] Handlers use repository interfaces only

---

## Implementation Steps

### 1. List Conversations Query

Create `src/application/queries/list-conversations/`:
- `list-conversations.query.ts` — `filters: ConversationFilters`, `pagination: PaginationParams`
- `list-conversations.handler.ts`:
  1. Query MongoDB for conversations with filters and pagination
  2. Enrich with clinic name from PostgreSQL (optional, can be denormalized)
  3. Return `PaginatedResult<Conversation>`

### 2. Get Conversation Detail Query

Create `src/application/queries/get-conversation-detail/`:
- `get-conversation-detail.query.ts` — `conversationId: string`
- `get-conversation-detail.handler.ts`:
  1. Get conversation from MongoDB
  2. Get messages for conversation
  3. Get AI traces for conversation
  4. Return combined result
