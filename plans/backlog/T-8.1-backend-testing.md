# T-8.1 — Backend Testing

**Phase:** Testing
**Layer:** Backend
**Status:** Backlog
**Estimated Effort:** 3–4 hours
**Dependencies:** T-2.x through T-5.x

---

## Objective

Write unit tests for all backend layers: domain entities, CQRS handlers, repository contracts, tool validation, LLM orchestration, and API controllers.

---

## Acceptance Criteria

- [ ] Domain entity tests: appointment validation, status transitions, timezone handling
- [ ] CQRS handler tests: CreateAppointment, CancelAppointment, ProcessIncomingMessage
- [ ] Repository tests: mocked PrismaClient and MongoCollection
- [ ] Tool validation tests: Zod schemas reject invalid inputs, domain validation catches business rule violations
- [ ] LLM orchestration tests: iteration limits, error handling, escalation
- [ ] Controller tests: HTTP status codes, response shapes, error mapping
- [ ] No real database, LLM, or queue connections in unit tests
- [ ] Coverage ≥ 75%

---

## Implementation Steps

### 1. Domain Tests

```text
apps/api/src/domain/entities/appointment.entity.spec.ts
apps/api/src/domain/entities/slot.entity.spec.ts
```

Test business rules:
- Appointment cannot be created for a booked slot
- Past dates rejected
- Status transitions enforced

### 2. Handler Tests

```text
apps/api/src/application/commands/create-appointment/create-appointment.handler.spec.ts
apps/api/src/application/commands/cancel-appointment/cancel-appointment.handler.spec.ts
apps/api/src/application/commands/process-incoming-message/process-incoming-message.handler.spec.ts
```

Use mock repositories and event publishers.

### 3. Repository Tests

```text
apps/api/src/infrastructure/repositories/prisma-appointment.repository.spec.ts
apps/api/src/infrastructure/repositories/mongo-conversation.repository.spec.ts
```

Mock PrismaClient and MongoCollection, verify query shapes.

### 4. Tool Validation Tests

```text
apps/api/src/application/llm/tool-validation.spec.ts
```

Test each Zod schema with valid and invalid inputs.

### 5. Orchestration Tests

```text
apps/api/src/application/llm/ai-orchestrator.service.spec.ts
```

Use MockLLMService to test:
- Normal flow (no tools)
- Tool calling flow
- Iteration limit
- LLM error handling

### 6. Controller Tests

```text
apps/api/src/presentation/controllers/webhook.controller.spec.ts
apps/api/src/presentation/controllers/conversations.controller.spec.ts
```
