# T-1.2 — Domain Layer

**Phase:** Foundation
**Layer:** Backend
**Status:** Backlog
**Estimated Effort:** 2–3 hours
**Dependencies:** T-1.1

---

## Objective

Define the domain entities, enums, value objects, repository interfaces, service interfaces, domain events, and error classes. The domain layer must have zero dependencies on infrastructure.

---

## Acceptance Criteria

- [ ] `AppointmentStatus` enum: `CONFIRMED`, `CANCELLED`
- [ ] `ConversationStatus` enum: `ACTIVE`, `RESOLVED_BY_AI`, `APPOINTMENT_BOOKED`, `ESCALATED`
- [ ] Entity interfaces: `Clinic`, `Doctor`, `Slot`, `Appointment`, `Conversation`, `Message`, `AITrace`, `KnowledgeDocument`
- [ ] Repository interfaces: `AppointmentRepository`, `SlotRepository`, `KnowledgeRepository`, `ConversationRepository`, `MessageRepository`, `AITraceRepository`
- [ ] Service interfaces: `LLMService`, `EmbeddingService`, `QueueService`, `EventPublisher`
- [ ] Value objects: `DateRange`, `PaginationParams`, `PaginatedResult`, `ConversationFilters`, `KnowledgeResult`, `LLMChatParams`, `LLMChatResult`, `LLMToolDefinition`, `LLMToolCall`
- [ ] Domain events: `AppointmentCreatedEvent`, `AppointmentCancelledEvent`, `ConversationEscalatedEvent`
- [ ] Error classes: `SlotAlreadyBookedError`, `SlotNotFoundError`, `ClinicNotFoundError`, `PastDateError`, `LLMProviderError`, `LLMIterationLimitError`, `ValidationError`
- [ ] DI tokens for all repositories and services (Symbol-based)
- [ ] No imports from `prisma`, `mongodb`, `openai`, `express`, or any infrastructure package

---

## Implementation Steps

### 1. Enums

Create `src/domain/enums/`:
- `appointment-status.enum.ts` — `CONFIRMED`, `CANCELLED`
- `conversation-status.enum.ts` — `ACTIVE`, `RESOLVED_BY_AI`, `APPOINTMENT_BOOKED`, `ESCALATED`

### 2. Entity Interfaces

Create `src/domain/entities/`:
- `clinic.entity.ts`
- `doctor.entity.ts`
- `slot.entity.ts`
- `appointment.entity.ts`
- `conversation.entity.ts` (MongoDB)
- `message.entity.ts` (MongoDB)
- `ai-trace.entity.ts` (MongoDB)
- `knowledge-document.entity.ts` (PostgreSQL + pgvector)

### 3. Value Objects

Create `src/domain/value-objects/`:
- `date-range.vo.ts`
- `pagination.vo.ts` — `PaginationParams`, `PaginatedResult<T>`
- `conversation-filters.vo.ts`
- `knowledge-result.vo.ts`
- `llm-chat.vo.ts` — `LLMChatParams`, `LLMChatResult`, `LLMMessage`, `LLMToolDefinition`, `LLMToolCall`

### 4. Repository Interfaces

Create `src/domain/repositories/`:
- `appointment.repository.ts` — `create`, `findById`, `findBySlotId`, `findByPatientPhone`
- `slot.repository.ts` — `findAvailable`, `findById`, `markAsBooked`, `markAsAvailable`
- `knowledge.repository.ts` — `search`, `findByClinicId`
- `conversation.repository.ts` — `findByPatientPhone`, `findById`, `findAll`, `updateStatus`
- `message.repository.ts` — `create`, `findByConversationId`, `findByMessageId`
- `ai-trace.repository.ts` — `create`, `findByConversationId`

Each with a DI token: `export const APPOINTMENT_REPOSITORY = Symbol('AppointmentRepository');`

### 5. Service Interfaces

Create `src/domain/services/`:
- `llm.service.ts` — `LLMService` interface with `chat()` method
- `embedding.service.ts` — `EmbeddingService` interface with `embed()` method
- `queue.service.ts` — `QueueService` interface with `push()` method
- `event-publisher.interface.ts` — `EventPublisher` interface with `publish()` method

### 6. Domain Events

Create `src/domain/events/`:
- `domain-event.ts` — base interface
- `appointment-created.event.ts`
- `appointment-cancelled.event.ts`
- `conversation-escalated.event.ts`

### 7. Error Classes

Create `src/domain/errors/`:
- `slot-already-booked.error.ts`
- `slot-not-found.error.ts`
- `clinic-not-found.error.ts`
- `past-date.error.ts`
- `llm-provider.error.ts`
- `llm-iteration-limit.error.ts`
- `validation.error.ts`
