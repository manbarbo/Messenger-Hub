# T-3.3 — Tool Calling Validation

**Phase:** AI Pipeline
**Layer:** Backend
**Status:** Backlog
**Estimated Effort:** 2–3 hours
**Dependencies:** T-1.2

---

## Objective

Define Zod schemas for all tool arguments and implement a validation layer that checks LLM-proposed tool calls before execution. Validation errors are returned to the LLM as tool results.

---

## Acceptance Criteria

- [ ] Zod schema for `buscar_conocimiento`: `pregunta` (string, non-empty)
- [ ] Zod schema for `consultar_disponibilidad`: `especialidad` (string), `sede` (string), `fecha` (YYYY-MM-DD regex)
- [ ] Zod schema for `agendar_cita`: all consultar_disponibilidad fields + `hora` (HH:mm), `paciente_telefono` (string), `paciente_nombre?` (string)
- [ ] Zod schema for `escalar_a_humano`: `motivo` (string, non-empty)
- [ ] Domain validation layer: date not in past, clinic/specialty exists, slot available
- [ ] Validation errors formatted as tool result strings for LLM feedback
- [ ] `ToolValidator` service that combines Zod + domain validation
- [ ] Tool definitions in OpenAI function-calling format

---

## Implementation Steps

### 1. Tool Schemas (Zod)

Create `src/application/llm/tool-schemas.ts`:
```typescript
import { z } from 'zod';

export const BuscarConocimientoSchema = z.object({
  pregunta: z.string().min(1, 'La pregunta no puede estar vacía'),
});

export const ConsultarDisponibilidadSchema = z.object({
  especialidad: z.string().min(1),
  sede: z.string().min(1),
  fecha: z.string().regex(/^\d{4}-\d{2}-\d{2}$/, 'Formato de fecha inválido (YYYY-MM-DD)'),
});

export const AgendarCitaSchema = ConsultarDisponibilidadSchema.extend({
  hora: z.string().regex(/^\d{2}:\d{2}$/, 'Formato de hora inválido (HH:mm)'),
  paciente_telefono: z.string().min(1),
  paciente_nombre: z.string().optional(),
});

export const EscalarAHumanoSchema = z.object({
  motivo: z.string().min(1, 'El motivo no puede estar vacío'),
});
```
