# T-6.2 — Conversation Inbox View

**Phase:** Frontend
**Layer:** Frontend
**Status:** Backlog
**Estimated Effort:** 2–3 hours
**Dependencies:** T-6.1, T-5.1

---

## Objective

Implement the conversation inbox view with status filtering, pagination, and proper loading/error states.

---

## Acceptance Criteria

- [ ] `ConversationListComponent` displays paginated table of conversations
- [ ] Columns: Patient Phone, Clinic, Status (badge), Messages, Last Activity
- [ ] Status filter dropdown (all, active, resolved_by_ai, appointment_booked, escalated)
- [ ] Pagination controls at bottom
- [ ] Loading skeleton during fetch
- [ ] Empty state when no results
- [ ] Error message on fetch failure with retry button
- [ ] Click on conversation navigates to detail view
- [ ] Status badges color-coded: active (blue), resolved_by_ai (green), appointment_booked (purple), escalated (red)

---

## Implementation Steps

### 1. Conversation List Component

Create `app/conversations/conversation-list/conversation-list.component.ts`:
- Inject `ApiService`
- On init: load conversations with default filters
- On filter change: refetch
- On page change: refetch

### 2. Conversation List Template

```html
<app-layout>
  <div class="filters">
    <select [(ngModel)]="statusFilter" (change)="loadConversations()">
      <option value="">All statuses</option>
      <option value="active">Active</option>
      <option value="resolved_by_ai">Resolved by AI</option>
      <option value="appointment_booked">Appointment Booked</option>
      <option value="escalated">Escalated</option>
    </select>
  </div>

  @if (loading) {
    <app-loading-spinner />
  } @else if (error) {
    <app-error-message [message]="error" (retry)="loadConversations()" />
  } @else if (conversations.length === 0) {
    <div class="empty-state">No conversations found</div>
  } @else {
    <table>
      <!-- conversation rows -->
    </table>
    <app-pagination [page]="page" [totalPages]="totalPages" (pageChange)="onPageChange($event)" />
  }
</app-layout>
```
