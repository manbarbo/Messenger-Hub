# T-10.3 — Backend: Knowledge Documents REST API

**Phase:** Phase 10 — RAG Knowledge Base Management
**Layer:** Backend
**Status:** Backlog
**Priority:** high
**Estimated Effort:** 2–3 hours
**Depends on:** T-10.2 (CQRS handlers)
**Blocks:** T-10.4 (frontend knowledge list)

---

## Objective

Expose a REST controller for RAG knowledge documents so the dashboard can consult, create, update, and delete documents. Controllers only validate input (Zod) and delegate to CQRS buses; domain errors map through the existing `DomainExceptionFilter`.

---

## Acceptance Criteria

- [ ] `KnowledgeDocumentsController` registered under `api/knowledge` in `PresentationModule`
- [ ] Endpoints:
  - `GET /api/knowledge?clinicId=&category=&page=&pageSize=` → paginated list
  - `GET /api/knowledge/:id` → single document (200) or domain 404
  - `POST /api/knowledge` → create (201)
  - `PATCH /api/knowledge/:id` → partial update (200)
  - `DELETE /api/knowledge/:id` → delete (204 or 200 with `{ deleted: true }`)
- [ ] Request bodies/queries validated with Zod schemas (`presentation/dto/knowledge-document.schema.ts`):
  - List: `clinicId` required UUID/string non-empty; optional `category`, `page` ≥ 1, `pageSize` 1–100
  - Create: `clinicId`, `title`, `content`, `category` required non-empty
  - Update: at least one of `title` | `content` | `category` present
  - Path param `:id` non-empty
- [ ] Invalid input → 400 via existing Zod error formatting (`formatZodErrors`) + `BadRequestException` pattern used by other controllers
- [ ] Domain errors (`KnowledgeDocumentNotFoundError`, `ValidationError`) → handled by global `DomainExceptionFilter` (no try/catch leaking infra errors in controller)
- [ ] Controllers use `CommandBus` / `QueryBus` only (no direct repositories)
- [ ] Structured logging not required in controller beyond what interceptor provides; handlers already log mutations
- [ ] Unit tests: controller happy paths + Zod validation failures for each endpoint
- [ ] DESIGN.md §5 API Contracts documents all 5 knowledge endpoints
- [ ] README.md endpoint table includes the knowledge routes
- [ ] Existing tests still pass

## Implementation Steps

### 1. Zod schemas

Create `apps/api/src/presentation/dto/knowledge-document.schema.ts` (same style as `simulator.schema.ts` / `list-conversations.schema.ts`):

```ts
export const ListKnowledgeQuerySchema = z.object({
  clinicId: z.string().trim().min(1),
  category: z.string().trim().min(1).optional(),
  page: z.coerce.number().int().min(1).optional(),
  pageSize: z.coerce.number().int().min(1).max(100).optional(),
});

export const CreateKnowledgeBodySchema = z.object({
  clinicId: z.string().trim().min(1),
  title: z.string().trim().min(1),
  content: z.string().trim().min(1),
  category: z.string().trim().min(1),
});

export const UpdateKnowledgeBodySchema = z
  .object({
    title: z.string().trim().min(1).optional(),
    content: z.string().trim().min(1).optional(),
    category: z.string().trim().min(1).optional(),
  })
  .refine((body) => body.title !== undefined || body.content !== undefined || body.category !== undefined, {
    message: 'at least one of title, content, category is required',
  });
```

### 2. Controller

Create `apps/api/src/presentation/controllers/knowledge-documents.controller.ts`:

```ts
@Controller('api/knowledge')
export class KnowledgeDocumentsController {
  constructor(
    private readonly commandBus: CommandBus,
    private readonly queryBus: QueryBus,
  ) {}

  @Get()
  list(@Query() query: unknown) { /* Zod parse → ListKnowledgeDocumentsQuery */ }

  @Get(':id')
  get(@Param('id') id: string) { /* GetKnowledgeDocumentQuery */ }

  @Post()
  create(@Body() body: unknown) { /* CreateKnowledgeDocumentCommand → 201 */ }

  @Patch(':id')
  update(@Param('id') id: string, @Body() body: unknown) { /* UpdateKnowledgeDocumentCommand */ }

  @Delete(':id')
  async remove(@Param('id') id: string) { /* DeleteKnowledgeDocumentCommand → { deleted: true } */ }
}
```

### 3. Module registration

Add `KnowledgeDocumentsController` to `presentation.module.ts` controllers array.

### 4. Tests

`knowledge-documents.controller.spec.ts` with mocked `CommandBus` / `QueryBus`:
- list happy path + missing `clinicId` → 400
- create happy path + invalid body → 400
- update happy path + empty body → 400
- delete happy path
- get happy path
