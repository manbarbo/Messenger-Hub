# T-10.5 — Frontend: Knowledge Document CRUD (Add / Edit / Delete)

**Phase:** Phase 10 — RAG Knowledge Base Management
**Layer:** Frontend
**Status:** Backlog
**Priority:** high
**Estimated Effort:** 3–4 hours
**Depends on:** T-10.4 (knowledge list), T-10.3 (`POST`/`PATCH`/`DELETE /api/knowledge`)
**Blocks:** —

---

## Objective

Complete the Knowledge Base management UI: create new RAG documents, edit existing ones (title/content/category), and delete with confirmation. After mutations, the list refreshes so operators can immediately verify what the assistant will retrieve via RAG.

---

## Acceptance Criteria

- [ ] `ApiService.createKnowledgeDocument(body)` → `POST /api/knowledge`
- [ ] `ApiService.updateKnowledgeDocument(id, body)` → `PATCH /api/knowledge/:id`
- [ ] `ApiService.deleteKnowledgeDocument(id)` → `DELETE /api/knowledge/:id`
- [ ] List view gains a primary action **"New document"** (opens create form)
- [ ] Create/Edit form (dialog or dedicated panel) fields:
  - Clinic select (disabled on edit — document clinic is immutable in MVP)
  - Title (required, min 1)
  - Category (required, min 1; free text or select + free text combo)
  - Content (required textarea)
- [ ] Client-side validation messages for empty fields; submit disabled while invalid or in-flight
- [ ] Create success → close form, success feedback (snackbar/toast or inline), list reloads
- [ ] Edit preloads current values from detail (`getKnowledgeDocument`) before PATCH
- [ ] Delete: confirmation dialog ("Delete document X? This removes it from RAG retrieval.") → `deleteKnowledgeDocument` → list reloads + success feedback
- [ ] Error handling: API failure shows error message via shared `app-error-message` or form-level error; `LoggerService.error` with context (no document content in logs if considered sensitive — title/category OK; do not log full content body)
- [ ] Mutations do not implement business rules beyond form validation (backend remains source of truth)
- [ ] Component tests:
  - Open create form, validation blocks empty submit, successful create calls ApiService and refreshes list
  - Open edit form, preloads fields, successful update calls ApiService
  - Delete confirmation cancel does not call API; confirm calls delete and refreshes
  - Error paths surface messages
- [ ] `api.service.spec.ts` extended for create/update/delete
- [ ] Frontend tests + lint pass; coverage not reduced
- [ ] DESIGN.md §6 notes Knowledge Base management interactions

---

## Implementation Steps

### 1. ApiService mutations

Add create/update/delete methods (logger.debug/info without full content payload).

### 2. Knowledge form component

Create `apps/web/src/app/knowledge/knowledge-form/` (dialog or reusable component):
- Inputs: mode (`create` | `edit`), optional `KnowledgeDocumentDetail`
- Outputs: `saved`, `cancelled`
- Reactive forms or signal-based form with validation

### 3. Delete confirmation

Use Angular Material dialog (same pattern style as any existing confirm if present; otherwise small `ConfirmDialogComponent` under `shared/`).

### 4. Wire into KnowledgeListComponent

- Toolbar: "New document"
- Row actions: Edit, Delete
- After `saved` / delete success: reload current page filters
- Open edit via `getKnowledgeDocument(id)` then form

### 5. Tests

Extend list component spec + new form/confirm specs + ApiService spec.
