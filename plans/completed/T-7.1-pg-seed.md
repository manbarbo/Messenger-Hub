## Implementation Notes

### Model change: `text-embedding-004` → `gemini-embedding-001`

During verification the Gemini OpenAI-compatible endpoint returned `404 models/text-embedding-004 is not found`. Available embedding models include `gemini-embedding-001` and `gemini-embedding-2`, both supporting explicit `dimensions: 768` (required to match `vector(768)`).

Updated:

- `apps/api/.env` + `.env.example`: `EMBEDDING_MODEL=gemini-embedding-001`
- `GeminiEmbeddingService` + seed `embedding-client`: default model + pass `dimensions` to the provider
- Docs/skills that referenced the old model name

### Seed structure

```text
apps/api/prisma/
├── seed.ts                          # Orchestrator (reset + create + embed)
└── seeds/
    ├── types.ts                     # Shared constants/types + toPgVector
    ├── clinic-data.ts               # 2 clinics + 8 doctors
    ├── knowledge-documents.ts       # 12 docs (6 categories × 2 clinics)
    ├── slot-generator.ts            # Pure Colombia weekday slot times (UTC-5)
    ├── embedding-client.ts          # OpenAI SDK → Gemini embeddings
    └── *.spec.ts                    # Unit tests for pure helpers
```

### Behavior

- **Idempotent:** skips when Clínica Norte/Clínica Sur + ≥ 8 knowledge documents already exist.
- **`SEED_RESET=true`:** wipes appointments → slots → knowledge → doctors → clinics, then reseeds.
- **Incomplete/legacy data:** wiped and reseeded to the target dataset.
- **Slots:** generated in Colombia wall-clock (UTC-5), stored as UTC `TIMESTAMPTZ`.
- **Embeddings:** document created without embedding, then raw SQL `UPDATE ... SET embedding = $1::vector` (same pattern as `PrismaKnowledgeRepository.create`).
