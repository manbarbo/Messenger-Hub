## Objective

Implement the RAG pipeline: embedding service using Google `text-embedding-004` and knowledge search via pgvector cosine similarity.

---

## Acceptance Criteria

- [x] `GeminiEmbeddingService` implementing `EmbeddingService` interface
- [x] Uses Google's embedding API (via OpenAI-compatible endpoint or native)
- [x] Returns 768-dimensional vectors
- [x] `KnowledgeRepository.search()` uses cosine distance with threshold > 0.7
- [x] Returns top 5 matching documents with title, content, category, and similarity score
- [x] If no documents match threshold, returns empty array (LLM handles "no info" response)
- [x] `EmbeddingModule` providing `EmbeddingService` via DI

---

## Implementation Steps

### 1. Gemini Embedding Service

Create `src/infrastructure/embeddings/gemini-embedding.service.ts`:
- OpenAI client configured with `LLM_API_KEY` + `LLM_BASE_URL`
- Model from `EMBEDDING_MODEL` (default `text-embedding-004`)
- Dimensions validated against `EMBEDDING_DIMENSIONS` (default `768`)
- Empty/whitespace text → `ValidationError`
- Provider failures / empty vectors → `LLMProviderError`
- Dimension mismatch → `ValidationError`

### 2. Knowledge Search Integration

Verified existing `PrismaKnowledgeRepository.search()` from T-2.1:
- Embeds query via `EMBEDDING_SERVICE`
- Cosine distance: `1 - (embedding <=> $1::vector) > 0.7`
- Default limit 5, ordered by distance
- Returns `KnowledgeResult` with title, content, category, similarity
- Empty result set when nothing exceeds the threshold

### 3. Embedding Module

Create `src/infrastructure/embeddings/embedding.module.ts`:
- `@Global` module providing `{ provide: EMBEDDING_SERVICE, useClass: GeminiEmbeddingService }`
- Exports `EMBEDDING_SERVICE` so `InfrastructureModule` can inject it into `PrismaKnowledgeRepository`
- Parallel to `DatabaseModule` (global infrastructure providers)

### 4. AppModule Wiring

Wired `AppModule` now that `EMBEDDING_SERVICE` exists (deferred by T-2.1–T-2.4):
- Imports: `ConfigModule`, `EventEmitterModule`, `DatabaseModule`, `EmbeddingModule`, `LlmModule`, `InfrastructureModule`, `ApplicationModule`

---

## Implementation Notes

- Knowledge search behavior was already implemented in T-2.1; this task delivers the embedding adapter + DI module that search depends on.
- `EmbeddingModule` is `@Global` so `InfrastructureModule` can resolve `EMBEDDING_SERVICE` without a direct import edge (same pattern as `DatabaseModule` → `PrismaService`).
- Dimension check uses `EMBEDDING_DIMENSIONS` so the adapter stays consistent with the pgvector `vector(768)` column.
- "No relevant information found" message handling belongs to the orchestrator/tool layer (T-3.3/T-3.4), not the repository.
