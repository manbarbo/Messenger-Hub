## Objective

Implement PostgreSQL repository adapters using Prisma: `PrismaAppointmentRepository`, `PrismaSlotRepository`, `PrismaKnowledgeRepository`.

---

## Acceptance Criteria

- [x] `PrismaAppointmentRepository` implementing `AppointmentRepository` interface
- [x] `PrismaSlotRepository` implementing `SlotRepository` interface
- [x] `PrismaKnowledgeRepository` implementing `KnowledgeRepository` interface (pgvector cosine search)
- [x] Appointment creation is transactional: `INSERT` appointment + `UPDATE slot.is_booked = true` in a single Prisma transaction
- [x] `findBySlotId()` for idempotency checks
- [x] `findAvailable()` filters by `clinic_id`, specialty (via doctor join), date, and `is_booked = false`
- [x] Knowledge search uses `embedding <=> $1` cosine distance with threshold > 0.7
- [x] `InfrastructureModule` binding interfaces to implementations via NestJS DI tokens

## Implementation Steps

### 1. Appointment Repository

Create `src/infrastructure/repositories/prisma-appointment.repository.ts`:
- `create()` — Transaction: `prisma.$transaction([prisma.appointment.create, prisma.slot.update])`
- `findById()` — `prisma.appointment.findUnique`
- `findBySlotId()` — `prisma.appointment.findUnique({ where: { slotId } })`
- `findByPatientPhone()` — `prisma.appointment.findMany({ where: { patientPhone } })`

### 2. Slot Repository

Create `src/infrastructure/repositories/prisma-slot.repository.ts`:
- `findAvailable()` — Join with `doctors` table for specialty filter, filter by `is_booked = false` and date range
- `findById()` — `prisma.slot.findUnique`
- `markAsBooked()` — `prisma.slot.update({ data: { isBooked: true } })`
- `markAsAvailable()` — `prisma.slot.update({ data: { isBooked: false } })`

### 3. Knowledge Repository

Create `src/infrastructure/repositories/prisma-knowledge.repository.ts`:
- `search()` — Embed query via `EmbeddingService`, then raw SQL with cosine distance:
  ```sql
  SELECT id, title, content, category,
         1 - (embedding <=> $1::vector) AS similarity
  FROM knowledge_documents
  WHERE clinic_id = $2
    AND 1 - (embedding <=> $1::vector) > 0.7
  ORDER BY embedding <=> $1::vector
  LIMIT $3
  ```
- `findByClinicId()` — `prisma.knowledgeDocument.findMany`

### 4. Infrastructure Module

Update `src/infrastructure/infrastructure.module.ts` to bind:
- `APPOINTMENT_REPOSITORY` → `PrismaAppointmentRepository`
- `SLOT_REPOSITORY` → `PrismaSlotRepository`
- `KNOWLEDGE_REPOSITORY` → `PrismaKnowledgeRepository`

## Implementation Notes

- `create()` validates slot availability inside the interactive transaction (`SlotNotFoundError` / `SlotAlreadyBookedError`) so appointment INSERT + slot UPDATE stay atomic under concurrency.
- Domain `Appointment.status` is mapped from Prisma's string enum via `toDomain` (Prisma `$Enums.AppointmentStatus` is not nominally assignable to the domain enum).
- `PrismaKnowledgeRepository.search()` embeds the query through `EMBEDDING_SERVICE`, formats a pgvector literal, and filters with `RAG_SIMILARITY_THRESHOLD` (0.7). Default limit is 5.
- `KnowledgeDocument.embedding` is `Unsupported("vector(768)")` in Prisma; `create()` persists embeddings via `$executeRaw` UPDATE after the base row insert.
- `findAvailable()` filters `doctor.specialty` + `doctor.active = true`, with UTC day boundaries derived from the provided `date`.
- `InfrastructureModule` binds the three tokens and exports them. It depends on `PrismaService` (provided by global `DatabaseModule`) and `EMBEDDING_SERVICE` (provided by `EmbeddingModule` in T-3.2). AppModule wiring of `InfrastructureModule` is deferred until T-3.2 so the app stays bootable before the embedding adapter exists.
- Unit tests mock `PrismaService` (including `$transaction` interactive callback) and `EmbeddingService`; no real database required.
