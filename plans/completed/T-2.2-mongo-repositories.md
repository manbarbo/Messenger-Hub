## Implementation Steps

### 1. Conversation Repository

Create `src/infrastructure/repositories/mongo-conversation.repository.ts`:
- `findByPatientPhone()` — `collection.findOne({ clinicId, patientPhone, status: { $ne: 'escalated' } })`
- `findById()` — `collection.findOne({ _id: id })`
- `findAll()` — `collection.find({ clinicId, ...filters }).sort({ lastMessageAt: -1 }).skip().limit()`
- `updateStatus()` — `collection.updateOne({ _id: id }, { $set: { status, updatedAt } })`
- `create()` — `collection.insertOne(document)`

### 2. Message Repository

Create `src/infrastructure/repositories/mongo-message.repository.ts`:
- `create()` — `collection.insertOne(message)` with try/catch for duplicate key error on `message_id`
- `findByConversationId()` — `collection.find({ conversationId }).sort({ createdAt: 1 })`
- `findByMessageId()` — `collection.findOne({ messageId })`

### 3. AI Trace Repository

Create `src/infrastructure/repositories/mongo-ai-trace.repository.ts`:
- `create()` — `collection.insertOne(trace)`
- `findByConversationId()` — `collection.find({ conversationId }).sort({ turnIndex: 1 })`

### 4. Infrastructure Module Updates

- `CONVERSATION_REPOSITORY` → `MongoConversationRepository`
- `MESSAGE_REPOSITORY` → `MongoMessageRepository`

## Implementation Notes

- `MongoService` (global `DatabaseModule`) supplies collections: `conversations`, `messages`, `ai_traces`.
- Document shapes use camelCase fields matching `MONGO_INDEX_SPECS` (`messageId`, `conversationId`, `turnIndex`, `clinicId`, `lastMessageAt`). Domain `_id` maps to document `_id`.
- Document types are TypeScript `type` aliases (not `interface`) so they satisfy `MongoService.getCollection<T extends Record<string, unknown>>`.
- `findByPatientPhone()` excludes `ConversationStatus.ESCALATED` via `$nin` and always scopes by `clinicId` + `patientPhone`.
- `findAll()` applies `clinicId`, `status`, and `patientPhone` when present in `ConversationFilters`, sorts by `lastMessageAt` desc, and returns `createPaginatedResult` (domain `PaginatedResult` shape: `items`, `pageSize`).
- `MongoMessageRepository.create()` catches Mongo duplicate-key errors (`code === 11000`) and returns silently for idempotent reprocessing; other errors rethrow. Unique sparse index on `messageId` is the source of truth.
- Tenant scoping: methods that receive `clinicId` or query by unique conversation/message ids always carry `clinicId` on written documents; `findById` / `findByConversationId` / `findByMessageId` use natural unique keys as defined by the domain interfaces.
- `InfrastructureModule` now binds all six repository tokens (3 Prisma + 3 Mongo). AppModule wiring still deferred until T-3.2 (`EMBEDDING_SERVICE`).
- Unit tests mock `MongoService` → collection + chainable cursor (`sort`/`skip`/`limit`/`toArray`).
