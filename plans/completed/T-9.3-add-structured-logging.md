# T-9.3 — Add Structured Logging Across Application

**Phase:** Logging
**Layer:** Full Stack
**Status:** Completed
**Completed:** 2026-10-03
**Estimated Effort:** 4-6 hours
**Dependencies:** T-9.1, T-9.2

---

## Objective

Add structured logging to all critical paths in the backend and frontend using the `LOGGER` token (backend) and `LoggerService` (frontend) implemented in T-9.1 and T-9.2. Replace all existing NestJS `new Logger()` and `console.*` calls with the structured logger. Add logging to state mutations, external calls (LLM, embedding, DB), error paths, and user-facing operations.

---

## Acceptance Criteria

- [x] All `new Logger(...)` in backend replaced with `@Inject(LOGGER)`
- [x] All `console.*` in backend replaced with `logger.*()`
- [x] `console.error` in frontend `main.ts` bootstrap catch replaced with structured output
- [x] AI orchestrator logs turn start, tool calls, validation failures, escalation, turn completion
- [x] LLM adapter logs requests, responses (tokens, latency, cost), and errors
- [x] Embedding adapter logs requests and errors
- [x] CQRS command handlers log success and domain error paths
- [x] Database services log connection lifecycle (connect, disconnect, error)
- [x] Queue worker logs job lifecycle (start, retry, DLQ, complete, close)
- [x] Frontend components log data loading, user actions, and errors
- [x] All logs use structured metadata (context, relevant IDs, status)
- [x] No PII (patient phone, message content) in logs
- [x] All existing tests pass
- [x] No new lint errors

#### 1. `application/llm/ai-orchestrator.service.ts`

**Current:** Uses `new Logger(AIOrchestratorService.name)` + partial `.warn()` calls
**Action:** Migrate to `@Inject(LOGGER)` + add extensive logging

| Log Point | Level | Metadata |
|-----------|-------|----------|
