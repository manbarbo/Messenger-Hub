## Objective

Implement the `LLMService` adapter using the OpenAI SDK pointed at the Gemini endpoint. Support tool calling with iteration control.

---

## Acceptance Criteria

- [x] `GeminiLLMService` implementing `LLMService` interface
- [x] Uses OpenAI SDK with `baseURL` from `LLM_BASE_URL` env var
- [x] `chat()` method sends messages + tool definitions, returns content + tool calls + usage
- [x] Supports multi-turn tool calling: when LLM returns tool calls, caller can send results back
- [x] Handles LLM errors (timeout, rate limit, invalid response) gracefully
- [x] Returns structured `LLMChatResult` with `model`, `latencyMs`, `usage`
- [x] `LLMModule` providing `LLMService` via DI
- [x] `MockLLMService` for testing (returns pre-defined responses)

## Implementation Steps

### 1. Gemini LLM Service

Create `src/infrastructure/llm/gemini-llm.service.ts`:
- OpenAI client configured with `LLM_API_KEY` + `LLM_BASE_URL` via `ConfigService`
- Maps domain `LLMMessage[]` → OpenAI `ChatCompletionMessageParam[]` (including assistant `tool_calls` and `tool` results)
- Maps domain `LLMToolDefinition[]` → OpenAI function tools; sends `tool_choice: 'auto'` only when tools are present
- Parses tool-call JSON arguments into `Record<string, unknown>`; invalid JSON throws `LLMProviderError`
- Returns domain `LLMChatResult` (`content`, `toolCalls`, `model`, `inputTokens`, `outputTokens`, `latencyMs`, `costUsd`, `finishReason`)
- Cost estimate uses Gemini 2.5 Flash pricing from DECISIONS.md ($0.75/M input, $3.75/M output)
- Provider failures, empty responses, and invalid tool-call payloads are wrapped in `LLMProviderError`

### 2. Mock LLM Service

Create `src/infrastructure/llm/mock-llm.service.ts`:
- `setResponses()` scripts ordered `LLMChatResult` values
- `chat()` returns the next scripted response, then falls back to a default
- Records `calls` for test assertions; `callCount` exposes iteration count

### 3. LLM Module

Create `src/infrastructure/llm/llm.module.ts`:
- Provides `{ provide: LLM_SERVICE, useClass: GeminiLLMService }`
- Exports `LLM_SERVICE` for application layers
- AppModule wiring remains deferred until T-3.2, consistent with prior infrastructure tasks

---

## Implementation Notes

- Implemented against the domain `LLMChatResult` contract (flat token/cost fields), not the illustrative `usage` object in the original step sketch.
- Domain `LLMMessage.content` is `string`; assistant turns that only contain tool calls use `''` when sent back to the provider.
- Multi-turn support lives in `chat()` message mapping — the orchestrator (T-3.4) composes assistant + tool-result messages and enforces the 5-iteration limit.
- `LLMProviderError` is the only error type surfaced by the adapter; callers escalate on it.
