# T-9.6: Frontend — Chat-like Patient Simulator

**Status:** completed (2026-10-03)
**Priority:** high
**Depends on:** T-9.5 (clinic dropdowns), T-6.3 (message timeline)
**Blocks:** —

## Objective

Transform the Patient Simulator into a WhatsApp-like chat window: after the first message, show the conversation timeline, wait for the assistant reply, and allow follow-up messages in the same conversation.

## Approach

Frontend-only MVP. No new backend endpoint:

1. After first accepted `POST /api/simulator`, switch to chat mode.
2. Lock phone + clinic (conversation key is phone + clinicId).
3. Render `MessageTimelineComponent` with messages.
4. Poll `GET /api/conversations/:id` until assistant reply with `messageId === 'assistant:' + sentInboundMessageId` (or timeout ~60s).
5. Composer sends follow-ups; backend reuses the same conversation.

WebSockets are out of scope (AGENTS.md §22).

## Implementation Steps

1. Read `message-timeline` component API and conversation models.
2. Update `SimulatorComponent`:
   - signals: `mode` ('form' | 'chat'), `conversationId`, `messages`, `pending`, `pollError`
   - form mode: existing form + clinic select
   - chat mode: header (locked phone/clinic) + timeline + composer
3. Polling via RxJS `timer` + `switchMap(getConversation)`, stop on assistant messageId or max attempts.
4. Follow-up send with same phone + clinicId.
5. Tests + DESIGN.md §6 update.
6. Move plan to `plans/completed/`.
