## Objective

Add a Knowledge Base management view to the Angular dashboard that lists RAG documents for a selected clinic (consult), with filters, pagination, loading/error/empty states, and navigation entry point. This is the read surface of Phase 10; mutations arrive in T-10.5.

## Implementation Notes

- List response type reuses `ListConversationsResponse<KnowledgeDocumentSummary>` (same `{ data, pagination }` contract as conversations).
- Category filter options are derived from the **current page** of documents (no extra categories endpoint).
- Detail dialog is an in-component overlay (no MatDialog dependency); View button reserved for T-10.5 to add Edit/Delete actions.
- When no clinic is selected (or clinics fail to load), list shows guidance empty state and does not call `GET /api/knowledge`.

## Implementation Steps

### 1. Models

Create `apps/web/src/app/core/models/knowledge-document.model.ts` mirroring API contract from T-10.3.

### 2. ApiService

Add methods in `apps/web/src/app/core/api.service.ts` (follow `listConversations` HttpParams style).

### 3. Component

Create `apps/web/src/app/knowledge/knowledge-list/`:
- Signals: `documents`, `clinics`, `clinicId`, `category`, `page`, `pageSize`, `loading`, `error`, `selectedDocument`
- On init: load clinics; default select first clinic (or empty state "Select a clinic")
- Reload on clinic/category/page change (reset page to 1 on filter change)
- Detail: `getKnowledgeDocument(id)` → dialog or side panel with title/category/content

### 4. Routes + navigation

- `app.routes.ts`: `{ path: 'knowledge', component: KnowledgeListComponent }`
- `layout.component.html`: add nav link

### 5. Tests

Component + ApiService specs (mock `ApiService` with `of(...)` / errors).
