## Objective

Implement CQRS query handlers for data retrieval: `ListConversationsQuery`, `GetConversationDetailQuery`.

---

## Acceptance Criteria

- [x] `ListConversationsQuery` + handler: returns paginated conversations with optional status filter
- [x] `GetConversationDetailQuery` + handler: returns conversation with messages and AI traces
- [x] Queries combine data from both PostgreSQL (clinic name) and MongoDB (conversations, messages, traces)
- [x] Pagination works correctly with total count
- [x] Handlers use repository interfaces only

---

## Implementation Steps

### 1. List Conversations Query

Create `src/application/queries/list-conversations/`:
- `list-conversations.query.ts` — `filters: ConversationFilters`, `pagination: PaginationParams`
- `list-conversations.handler.ts`:
  1. Query MongoDB for conversations with filters and pagination
  2. Enrich with clinic name from PostgreSQL (optional, can be denormalized)
  3. Return `PaginatedResult<Conversation>`

### 2. Get Conversation Detail Query

Create `src/application/queries/get-conversation-detail/`:
- `get-conversation-detail.query.ts` — `conversationId: string`
- `get-conversation-detail.handler.ts`:
  1. Get conversation from MongoDB
  2. Get messages for conversation
  3. Get AI traces for conversation
  4. Return combined result

---

## Implementation Notes

- Added domain port `ClinicRepository` (`findById`) + infrastructure adapter `PrismaClinicRepository` so queries can enrich with PostgreSQL clinic names (DESIGN.md GET /api/conversations contract).
- Added domain error `ConversationNotFoundError` for missing detail lookups.
- **ListConversationsHandler** (`@QueryHandler`): `ConversationRepository.findAll` (Mongo filters + pagination) then enriches each item with `clinicName` via `ClinicRepository` (cached per clinicId to avoid N+1). Returns `PaginatedResult<ConversationSummary>`.
- **GetConversationDetailHandler**: loads conversation, then `Promise.all` for clinic (PG), messages (Mongo), and AI traces (Mongo). Returns `ConversationDetailResult` aligned with DESIGN.md detail payload.
- Application DTOs in `application/dto/conversation-view.ts`: `ConversationSummary`, `ConversationDetailResult`.
- `ApplicationModule` now registers `QUERY_HANDLERS` alongside commands/events; still imports `CqrsModule` (QueryBus).
- `InfrastructureModule` binds `CLINIC_REPOSITORY` → `PrismaClinicRepository`.
- Controllers (T-5.1) will map HTTP query params (`status`, `clinicId`, `page`, `limit`) to `ListConversationsQuery`.
- AppModule wiring remains deferred until T-3.2 (`EMBEDDING_SERVICE`).
