# T-4.4 — BullBoard Queue Monitoring

**Phase:** Async Processing (extension)
**Layer:** Backend
**Status:** Completed
**Estimated Effort:** 1–2 hours
**Dependencies:** T-4.1, T-4.2, T-5.2
**Started:** 2026-10-03
**Completed:** 2026-10-03

---

## Objective

Integrate BullBoard as an operational UI adapter so developers and operators can review BullMQ queue state (`message-processing` + `message-processing-dlq`) — jobs, retries, failed jobs, and DLQ contents — without reading Redis or raw logs.

This is an **infrastructure/ops concern**, not a business feature. It must not leak into domain or application layers.

## Implementation Steps

### 1. Install dependencies

```bash
pnpm --filter api add @bull-board/api @bull-board/express
```

Keep `bullmq` as the existing dependency — BullBoard adapters consume `bullmq` `Queue` instances directly.

### 2. Expose queue instances from `BullMQQueueService`

Add an adapter-level accessor (not on domain `QueueService` — Interface Segregation):

```typescript
// bullmq-queue.service.ts
getQueues(): Queue[] {
  return [this.queue, this.dlq];
}
```

### 3. Create `BullBoardService` (infrastructure adapter)

Create `apps/api/src/infrastructure/queue/bull-board.service.ts`:

- Injects `BullMQQueueService`, `ConfigService`, `LOGGER`
- Builds BullBoard with Express adapter; base path set on `ExpressAdapter` (BullBoard v9 API):

```typescript
import { createBullBoard } from '@bull-board/api';
import { BullMQAdapter } from '@bull-board/api/bullMQAdapter';
import { ExpressAdapter } from '@bull-board/express';

const serverAdapter = new ExpressAdapter();
serverAdapter.setBasePath(basePath);
createBullBoard({
  queues: queues.map((queue) => new BullMQAdapter(queue)),
  serverAdapter,
});
```

- Mounts `serverAdapter.getRouter()` on the NestExpress app at `BULL_BOARD_PATH`
- Registers **both** main queue and DLQ so failed jobs are reviewable
- Logs `info` on mount: `{ context: 'BullBoardService', path, queues, auth }`
- Logs `warn` when disabled: `{ context: 'BullBoardService', event: 'disabled' }`

### 4. Enable/disable + auth rules

| Condition | Behavior |
|-----------|----------|
| `BULL_BOARD_ENABLED=true` | Board mounted |
| `BULL_BOARD_ENABLED=false` | Board not mounted |
| Unset + `NODE_ENV !== 'production'` | Board mounted (dev default) |
| Unset + `NODE_ENV === 'production'` | Board not mounted |
| `BULL_BOARD_USERNAME` + `BULL_BOARD_PASSWORD` set | HTTP basic auth middleware applied to board routes |
| Auth env vars unset | No auth (dev convenience) |

Auth via a small inline Express middleware in the adapter — no full authentication system (AGENTS.md §22).

### 5. Wire into Nest bootstrap

In `main.ts`:

```typescript
const app = await NestFactory.create<NestExpressApplication>(AppModule);
app.get(BullBoardService).mount(app);
```

- `BullBoardService` provided + exported from `QueueModule`
- Mounted only in the API process (`main.ts`), not the worker (`worker-main.ts`)

### 6. Env + docs

`.env.example`:

```bash
BULL_BOARD_ENABLED=true
BULL_BOARD_PATH=/admin/queues
# BULL_BOARD_USERNAME=admin
# BULL_BOARD_PASSWORD=change-me
```

README: document `http://localhost:3000/admin/queues`.

### 7. Tests

`bull-board.service.spec.ts` (11 tests) covers enable/disable, custom path, queue registration, basic auth accept/reject, mount/disable logging.

`queue.module.spec.ts` asserts `BullBoardService` is provided.

`bullmq-queue.service.spec.ts` asserts `getQueues()` returns main + DLQ.

## Implementation Notes

- **BullBoard v9 API:** `createBullBoard()` no longer returns `setBasePath`. Base path is set on `ExpressAdapter` before `createBullBoard`.
- **`getQueues()` only:** domain `QueueService` remains `push`-only (Interface Segregation). Queue instances are adapter-level.
- **No duplicate Redis connections:** board reuses `BullMQQueueService` queue instances via `getQueues()`.
- **Dev default enabled / production default disabled** via `NODE_ENV` when `BULL_BOARD_ENABLED` is unset.
- **Pre-existing type fix:** `gemini-embedding.service.spec.ts` `createConfigService` now accepts `string | undefined` values (blocked `tsc --noEmit` before this task).
- **Manual smoke** requires Redis + API; unit tests mock `@bull-board/*` and never touch Redis.

## Implementation Steps

### 1. Install dependencies

```bash
pnpm --filter api add @bull-board/api @bull-board/express
```

Keep `bullmq` as the existing dependency — BullBoard adapters consume `bullmq` `Queue` instances directly.

### 2. Expose queue instances from `BullMQQueueService`

Add an adapter-level accessor (not on domain `QueueService` — Interface Segregation):

```typescript
// bullmq-queue.service.ts
getQueues(): Queue[] {
  return [this.queue, this.dlq];
}

getQueueMap(): Record<string, Queue> {
  return {
    [MESSAGE_PROCESSING_QUEUE]: this.queue,
    [MESSAGE_PROCESSING_DLQ]: this.dlq,
  };
}
```

`getQueues()` is enough for the board; `getQueueMap()` is optional if named UI labels are desired later.

### 3. Create `BullBoardService` (infrastructure adapter)

Create `apps/api/src/infrastructure/queue/bull-board.service.ts`:

- Implements `OnModuleInit` (or a dedicated `setup(app)` called from bootstrap)
- Injects `BullMQQueueService`, `ConfigService`, `LOGGER`
- Builds BullBoard with Express adapter:

```typescript
import { createBullBoard } from '@bull-board/api';
import { BullMQAdapter } from '@bull-board/api/bullMQAdapter';
import { ExpressAdapter } from '@bull-board/express';

const serverAdapter = new ExpressAdapter();
const board = createBullBoard({
  queues: queues.map((queue) => new BullMQAdapter(queue)),
  serverAdapter,
});
board.setBasePath(this.basePath);
```

- Mounts `serverAdapter.getRouter()` on the NestExpress app at `BULL_BOARD_PATH`
- Registers **both** main queue and DLQ so failed jobs are reviewable
- Logs `info` on mount: `{ context: 'BullBoardService', path, queues: [...] }`
- Logs `warn` when disabled: `{ context: 'BullBoardService', event: 'disabled' }`
- Never throws on mount failure in unit tests — handle errors with `logger.error`

### 4. Enable/disable + auth rules

| Condition | Behavior |
|-----------|----------|
| `BULL_BOARD_ENABLED=true` | Board mounted |
| `BULL_BOARD_ENABLED=false` | Board not mounted |
| Unset + `NODE_ENV !== 'production'` | Board mounted (dev default) |
| Unset + `NODE_ENV === 'production'` | Board not mounted |
| `BULL_BOARD_USERNAME` + `BULL_BOARD_PASSWORD` set | HTTP basic auth middleware applied to board routes |
| Auth env vars unset | No auth (dev convenience) |

Auth via Express basic-auth middleware (implement a small guard function in the adapter — do not add a full authentication system; AGENTS.md §22).

### 5. Wire into Nest bootstrap

In `main.ts`:

```typescript
const app = await NestFactory.create<NestExpressApplication>(AppModule);
const bullBoard = app.get(BullBoardService);
await bullBoard.mount(app);
```

- Export `BullBoardService` from `QueueModule`
- Mount only in the API process (`main.ts`), not the worker (`worker-main.ts`) — operators review via the API host
- If `QueueModule` already imports the service, keep DI consistent (`useClass` / direct provider)

### 6. Env + docs

`.env.example` additions:

```bash
# BullBoard (queue review UI) — mounted on the API process
BULL_BOARD_ENABLED=true
BULL_BOARD_PATH=/admin/queues
# Optional HTTP basic auth for the board
# BULL_BOARD_USERNAME=admin
# BULL_BOARD_PASSWORD=change-me
```

README: document `http://localhost:3000/admin/queues` as the queue review UI in development.

### 7. Tests

Create `apps/api/src/infrastructure/queue/bull-board.service.spec.ts`:

| Test | Assertion |
|------|-----------|
| mounts when explicitly enabled | `mount` called with path |
| skips when explicitly disabled | `mount` not called |
| defaults to enabled in non-production | `mount` called |
| defaults to disabled in production | `mount` not called |
| uses custom `BULL_BOARD_PATH` | path passed to `setBasePath` |
| registers both queues | main + DLQ adapters |
| applies basic auth when creds set | middleware applied |
| logs mount lifecycle | `logger.info` called with context |
| logs disable path | `logger.warn` called with context |

Mock `@bull-board/api` and `@bull-board/express` modules (same pattern as `vi.mock('bullmq', ...)` in `queue.module.spec.ts`). Do not connect to real Redis in unit tests.

Update `queue.module.spec.ts` if `BullBoardService` is added as a provider.
