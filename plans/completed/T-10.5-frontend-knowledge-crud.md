## Objective

Complete the Knowledge Base management UI: create new RAG documents, edit existing ones (title/content/category), and delete with confirmation. After mutations, the list refreshes so operators can immediately verify what the assistant will retrieve via RAG.

- [x] `ApiService.updateKnowledgeDocument(id, body)` → `PATCH /api/knowledge/:id`

- [x] Create success → close form, snack bar feedback, list reloads

- [x] Delete: confirmation dialog (`ConfirmDialogComponent`) → `deleteKnowledgeDocument` → list reload + snack bar
- [x] Error handling: form-level / delete-level error messages; `LoggerService` without full content bodies
- [x] Mutations do not implement business rules beyond form validation (backend remains source of truth)
- [x] Component tests: create success/error, edit success, delete confirm/cancel/error, form validation
- [x] `api.service.spec.ts` extended for create/update/delete
- [x] Frontend tests + lint pass; coverage not reduced (94.12% stmts / 86.34% branch overall)
- [x] DESIGN.md §6 View 1c documents CRUD interactions

---

## Implementation Notes

- Form validation uses signal-based field errors rendered as accessible `<p role="alert">` (not `mat-error`, which requires reactive form controls).
- `KnowledgeFormComponent` emits a discriminated union payload (`mode: 'create' | 'edit'`) so the list orchestrates API calls.
- Success feedback uses `MatSnackBar` (same pattern as Simulator).
- Delete confirmation is an in-app overlay dialog (no MatDialog dependency).
- Logging: create/update log clinicId/category/titleLength/contentLength; never full content.

## Implementation Steps

### 1. ApiService mutations

Add create/update/delete methods (logger.debug/info without full content payload).

### 2. Knowledge form component

Create `apps/web/src/app/knowledge/knowledge-form/` (dialog or reusable component):
- Inputs: mode (`create` | `edit`), optional `KnowledgeDocumentDetail`
- Outputs: `saved`, `cancelled`
- Reactive forms or signal-based form with validation

### 3. Delete confirmation

Use Angular Material dialog (same pattern style as any existing confirm if present; otherwise small `ConfirmDialogComponent` under `shared/`).

### 4. Wire into KnowledgeListComponent

- Toolbar: "New document"
- Row actions: Edit, Delete
- After `saved` / delete success: reload current page filters
- Open edit via `getKnowledgeDocument(id)` then form

### 5. Tests

Extend list component spec + new form/confirm specs + ApiService spec.
