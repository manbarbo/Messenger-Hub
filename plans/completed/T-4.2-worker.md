## Objective

Implement the background worker that consumes messages from the queue, calls the AI orchestrator, and saves results.

---

## Acceptance Criteria

- [x] Worker consumes jobs from `message-processing` queue
- [x] Calls `AIOrchestratorService.processTurn()` with message data
- [x] Saves assistant response as outbound message in MongoDB
- [x] Updates conversation status based on orchestrator result
- [x] Saves AI trace with token counts, latency, tools called
- [x] Worker is idempotent (re-processing same message is safe)
- [x] Failed jobs retry up to 3 times before DLQ
- [x] Worker runs as a separate NestJS application (or microservice)

---

## Implementation Steps

### 1. Message Processor Service

Create `src/application/worker/message-processor.service.ts`:

- Injects `AIOrchestratorService`, `MESSAGE_REPOSITORY`, `CONVERSATION_REPOSITORY`
- `process(job: QueueJob)`:
  1. Idempotency check — outbound `messageId` is `assistant:${inboundMessageId}`; if already saved, skip
  2. Fail if conversation missing
  3. `aiOrchestrator.processTurn(conversationId, clinicId, text)`
  4. Save outbound assistant `Message` with deterministic `messageId`
  5. `conversationRepository.updateStatus(conversationId, result.status)`
- AI traces (tokens, latency, tools) are saved by `AIOrchestratorService.saveTrace` during `processTurn` — the worker does not duplicate that concern

### 2. BullMQ Worker Adapter (infrastructure)

Create `src/infrastructure/queue/bullmq-message.worker.ts`:

- Raw BullMQ `Worker` on `message-processing` (no `@nestjs/bullmq` — keeps BullMQ behind our own adapter boundary)
- Delegates each job to `MessageProcessorService`
- `failed` event: intermediate failures only warn (BullMQ retries); after `attemptsMade >= attempts` (3), push payload to DLQ via `BullMQQueueService.pushToDlq`
- `OnModuleInit` starts the worker; `OnModuleDestroy` closes it

### 3. Worker Module + Entry Point

- `src/application/worker/worker.module.ts` — imports Config, EventEmitter, Database, Embedding, LLM, Queue, Infrastructure, Cqrs, AIModule, ApplicationModule (CQRS booking handlers + event handlers)
- `src/worker-main.ts` — `NestFactory.createApplicationContext(WorkerModule)` with shutdown hooks
- `nest-cli.worker.json` + npm scripts: `start:worker`, `start:worker:dev`, `build:worker`

### 4. Related fixes

- `QueueModule` now exports `BullMQQueueService` (class token) alongside `QUEUE_SERVICE` via `useExisting` so the worker can call `pushToDlq`
- `AIOrchestratorService.dropPersistedCurrentMessage` — webhook persists inbound before enqueue; orchestrator strips a trailing history entry that matches the current user message so PromptBuilder does not duplicate the turn

---

## Implementation Notes

- Deviated from the plan sketch: no `@Processor`/`WorkerHost` (`@nestjs/bullmq` is not a dependency). Consumer lives in infrastructure as `BullMQMessageWorker`; application layer only has `MessageProcessorService` (Clean Architecture / AGENTS.md §10).
- Traces AC is satisfied by the orchestrator (already implemented in T-3.4), not re-implemented in the worker.
- Idempotency uses deterministic outbound `messageId` + pre-check; Mongo unique sparse index on `messageId` is a second line of defense.
- `WorkerModule` imports `ApplicationModule` so `CreateAppointmentCommand` (booking via orchestrator tool) resolves in the worker process.
