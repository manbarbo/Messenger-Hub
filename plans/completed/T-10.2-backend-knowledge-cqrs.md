## Objective

Implement CQRS application layer for RAG knowledge documents: commands to create/update/delete (with embedding generation via the existing `EmbeddingService` port) and queries to list/get documents by clinic. Handlers validate domain rules, log structured metadata, and never touch Prisma/Mongo/LLM SDKs directly.

## Implementation Notes

- List/get responses use DTOs in `application/dto/knowledge-document-view.ts` (`KnowledgeDocumentSummary`, `KnowledgeDocumentDetail`) — **no embedding arrays** on API-facing payloads.
- Embedding text: `` `${title}\n\n${content}` `` via `buildKnowledgeEmbeddingText`.
- `UpdateKnowledgeDocumentHandler` only calls `embeddingService.embed` when title or content actually change; category-only updates skip re-embed and pass `embedding: undefined` so the repository keeps the stored vector.
- Get query throws `KnowledgeDocumentNotFoundError` (not `null`) so REST can map cleanly to 404 via `DomainExceptionFilter`.
- Module DI test mocks extended for knowledge CRUD methods + `EMBEDDING_SERVICE`.

## Implementation Steps

### 1. Command classes

Follow `create-appointment.command.ts` style (plain classes with constructor params).

### 2. Create handler pattern

```ts
@CommandHandler(CreateKnowledgeDocumentCommand)
@Injectable()
export class CreateKnowledgeDocumentHandler implements ICommandHandler<CreateKnowledgeDocumentCommand> {
  constructor(
    @Inject(LOGGER) private readonly logger: Logger,
    @Inject(KNOWLEDGE_REPOSITORY) private readonly knowledgeRepository: KnowledgeRepository,
    @Inject(EMBEDDING_SERVICE) private readonly embeddingService: EmbeddingService,
  ) {}
  // validate → embed → repository.create → logger.info → return
}
```

### 3. Update handler

- `const existing = await repo.findById(command.id)` → not found → `KnowledgeDocumentNotFoundError`
- Build next document object from existing + overrides
- `const textChanged = next.title !== existing.title || next.content !== existing.content`
- If `textChanged`: `embedding = await embeddingService.embed(buildEmbeddingText(next))`
- Else: keep `existing.embedding` omitted on update payload (repository keeps DB embedding if not passed) — or explicitly skip embedding write
- `repo.update(next)` → log → return

### 4. Query handlers

- `ListKnowledgeDocumentsQueryHandler` → `repo.findMany(filters, pagination)`; return paginated result (exclude heavy `embedding` arrays from API-facing payload if needed via `KnowledgeDocumentSummary` DTO: `id`, `clinicId`, `title`, `category`, `createdAt`, `updatedAt`)
- `GetKnowledgeDocumentQueryHandler` → `repo.findById(id)`

### 5. Module registration

Register all 5 handlers in `apps/api/src/application/application.module.ts`.

### 6. Tests

Handler specs with mocked repos + embedding + logger (assert logger calls on mutation paths).
