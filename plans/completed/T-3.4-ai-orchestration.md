## Objective

Implement the AI orchestrator that manages the tool-calling loop: builds the prompt, calls the LLM, validates and executes tools, feeds results back, and enforces iteration limits.

---

## Acceptance Criteria

- [x] `AIOrchestratorService` that orchestrates a full conversation turn
- [x] System prompt includes current Colombia date/time and available tools
- [x] Conversation history loaded from MongoDB and included in prompt
- [x] Tool-calling loop: LLM → validate → execute → feed back → repeat
- [x] Maximum 5 iterations per turn; if reached, force escalation
- [x] Each tool call and result traced and saved to `ai_traces` collection
- [x] Handles LLM errors gracefully (timeout → escalation)
- [x] Returns final response content and conversation status
- [x] `AIModule` integrating orchestrator, LLM service, embedding service, tool validator

---

## Implementation Steps

### 1. Prompt Builder

Create `src/application/llm/prompt-builder.ts`:
- System prompt with clinic name + Colombia `YYYY-MM-DD HH:mm` (UTC-5)
- Anti-hallucination instructions + available tools list
- History mapped from MongoDB `Message[]` → `LLMMessage[]`
- `buildTurnMessages()` prepends the system message

### 2. AI Orchestrator Service

Create `src/application/llm/ai-orchestrator.service.ts`:
- Loads clinic name + conversation history
- Loop up to `MAX_TOOL_ITERATIONS = 5`:
  - `llm.chat({ messages, tools })`
  - No tool calls → `resolved_by_ai` + save trace
  - Tool calls → `ToolValidator.validate` → execute → feed result back
  - `agendar_cita` success → `appointment_booked` via `CreateAppointmentCommand`
  - `escalar_a_humano` → `escalated`
- Validation/execution errors are tool-result strings (not system failures)
- `LLMProviderError` → force escalation
- Iteration limit → force `escalar_a_humano` + escalate
- Saves `AITrace` with aggregated tokens/latency/cost and tool outcomes
- Knowledge search: empty / below 0.7 similarity → `"No relevant information found"`

### 3. AI Module + Wiring

Create `src/application/llm/ai.module.ts`:
- Imports `CqrsModule`, `LlmModule`, `EmbeddingModule`
- Providers: `PromptBuilder`, `ToolValidator`, `AIOrchestratorService`
- Exports orchestrator for worker/controllers (T-4.x / T-5.x)

Wiring:
- `ApplicationModule` imports `AIModule` (replaces local `ToolValidator` provider)
- `AppModule` imports `AIModule`

---

## Implementation Notes

- Booking goes through CQRS `CreateAppointmentCommand` (reuses slot/doctor/past-date rules + `AppointmentCreatedEvent`).
- `ToolValidator` enriches `agendar_cita` args with `clinicId`, `slotId`, `doctorId` before execution.
- Trace `finalStatus` maps to domain Spanish values: `resuelta_por_ia` | `cita_agendada` | `escalada`.
- Usage metrics accumulate across LLM iterations in a single trace per turn.
- Slot-race booking errors are fed back to the LLM as tool results so it can suggest alternatives.
