## Objective

Set up PostgreSQL with Prisma (schema, migrations, pgvector extension) and MongoDB (connection, indexes). Docker Compose must start both databases.

---

## Acceptance Criteria

- [x] Prisma schema (`apps/api/prisma/schema.prisma`) with all PostgreSQL models: `Clinic`, `Doctor`, `Slot`, `Appointment`, `KnowledgeDocument`
- [x] pgvector extension enabled via raw SQL migration
- [x] `vector(768)` column on `knowledge_documents` for embeddings
- [x] IVFFlat index on `knowledge_documents.embedding`
- [x] All indexes created: `slots(clinic_id, is_booked, start_time)`, `appointments(slot_id) UNIQUE`, `appointments(patient_phone)`, etc.
- [x] `PrismaService` extending `PrismaClient` with NestJS lifecycle hooks
- [x] MongoDB connection service (`MongoService`) with connection pooling
- [x] MongoDB indexes: `messages(message_id)` unique sparse, `messages(conversation_id, created_at)`, `conversations(clinic_id, status)`
- [x] `docker compose up -d` starts both databases
- [x] `npx prisma migrate dev` applies all migrations
- [x] `npx prisma db seed` runs seed script

---

## Implementation Notes

- Initial migration SQL includes `CREATE EXTENSION IF NOT EXISTS vector;` **before** tables that use `vector(768)`.
- IVFFlat cosine index: `idx_knowledge_docs_embedding ... USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100)`.
- `embedding` is **nullable** until T-7.1 seeds knowledge with embeddings (RAG pipeline).
- Minimal seed creates 1 clinic + 1 doctor + weekday slots (no LLM API key required).
- `MongoService` ensures indexes on startup; pure specs in `mongo-indexes.ts` + script `pnpm --filter api mongo:indexes`.
- `DatabaseModule` is `@Global` and exports `PrismaService` + `MongoService`.
