## Objective

Extend the domain port `KnowledgeRepository` and the `PrismaKnowledgeRepository` adapter with persistence operations required to consult, create, update, and delete RAG knowledge documents (pgvector), without breaking the existing `search()` RAG path.

---

## Acceptance Criteria

- [x] Domain error `KnowledgeDocumentNotFoundError` added (`documentId` optional, same pattern as `ClinicNotFoundError`) and exported from `domain/errors`
- [x] `KnowledgeRepository` extended with:
  - `findById(id: string): Promise<KnowledgeDocument | null>`
  - `findMany(filters: KnowledgeDocumentFilters, pagination: PaginationParams): Promise<PaginatedResult<KnowledgeDocument>>`
  - `update(document: KnowledgeDocument): Promise<KnowledgeDocument>`
  - `delete(id: string): Promise<void>`
- [x] Filters type supports `clinicId` (required for list) and optional `category`
- [x] `PrismaKnowledgeRepository.findById()` returns domain entity via existing `toDomain`
- [x] `PrismaKnowledgeRepository.findMany()` filters by `clinicId` + optional `category`, paginates (`skip`/`take`), returns `{ items, total, page, pageSize, totalPages }` (reuse `PaginatedResult`)
- [x] `PrismaKnowledgeRepository.update()` updates `title`, `content`, `category` via Prisma client and persists `embedding` via `$executeRaw` when `document.embedding` is provided (same pattern as `create()`)
- [x] `PrismaKnowledgeRepository.delete()` deletes the row by `id` via Prisma client
- [x] Existing `search()` and `create()` behavior unchanged
- [x] Structured logging: `debug` on list/find start, `info` on mutation success, `warn` on not-found path where applicable (context: `PrismaKnowledgeRepository`; no PII)
- [x] Unit tests: repository spec covers `findById`, `findMany` (filters + pagination mapping), `update` (with/without embedding), `delete`, not-found paths
- [x] Existing backend tests still pass

---

## Implementation Notes

- `update`/`delete` convert Prisma `P2025` (record not found) into domain `KnowledgeDocumentNotFoundError` so infrastructure errors are not leaked.
- `update` does **not** clear an existing embedding when `document.embedding` is omitted (only writes the vector when a new one is provided). Command handlers (T-10.2) re-embed when title/content change.
- `findMany` orders by `createdAt desc` for dashboard recency; pagination via `createPaginatedResult`.
- Pre-existing type errors in Phase 9 specs (`list-clinics`, `list-conversations`, `get-conversation-detail`) were fixed as part of verification:
  - `ListClinicsHandler.execute` now accepts `_query: ListClinicsQuery` (CQRS signature)
  - Clinic repository mocks include `findAll` and cast via `unknown as ClinicRepository`

## Implementation Steps

### 1. Domain error

Create `apps/api/src/domain/errors/knowledge-document-not-found.error.ts`:

```ts
export class KnowledgeDocumentNotFoundError extends Error {
  readonly documentId?: string;

  constructor(documentId?: string, message?: string) {
    super(message ?? `Knowledge document ${documentId ?? '(unknown)'} was not found`);
    this.name = 'KnowledgeDocumentNotFoundError';
    this.documentId = documentId;
  }
}
```

Export from `domain/errors/index.ts`.

### 2. Domain repository port

Extend `apps/api/src/domain/repositories/knowledge.repository.ts`:

```ts
export interface KnowledgeDocumentFilters {
  clinicId: string;
  category?: string;
}

export interface KnowledgeRepository {
  search(clinicId: string, query: string, limit?: number): Promise<KnowledgeResult[]>;
  findByClinicId(clinicId: string): Promise<KnowledgeDocument[]>;
  findById(id: string): Promise<KnowledgeDocument | null>;
  findMany(
    filters: KnowledgeDocumentFilters,
    pagination: PaginationParams,
  ): Promise<PaginatedResult<KnowledgeDocument>>;
  create(document: KnowledgeDocument): Promise<KnowledgeDocument>;
  update(document: KnowledgeDocument): Promise<KnowledgeDocument>;
  delete(id: string): Promise<void>;
}
```

Reuse `PaginationParams` / `PaginatedResult` from `@domain/value-objects/pagination.vo` (same as conversations).

### 3. Infrastructure adapter

Extend `apps/api/src/infrastructure/repositories/prisma-knowledge.repository.ts`:

- `findById`: `prisma.knowledgeDocument.findUnique({ where: { id } })` → `toDomain(row)`
- `findMany`: `findMany({ where: { clinicId, category }, orderBy: { createdAt: 'asc' }, skip, take })` + `count({ where })`; map with `toDomain`
- `update`: `prisma.knowledgeDocument.update({ where: { id }, data: { title, content, category } })`; if `document.embedding?.length`, `UPDATE knowledge_documents SET embedding = ...::vector WHERE id = ...::uuid` via `$executeRaw`
- `delete`: `prisma.knowledgeDocument.delete({ where: { id } })`

### 4. Tests

Extend `apps/api/src/infrastructure/repositories/prisma-knowledge.repository.spec.ts` with mocked `PrismaService` for the new methods (existing mock style).
